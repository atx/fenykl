# fenykl.dsp

A toolkit for the E-M10 Mark II's DSP, the engine that runs horizontal microcode words of
`fields.WORD_BITS` (320) bits from DRAM. It has four parts:

- a codec: every bit of a word belongs to one field, each field but the constants to one unit,
  and any value decodes and encodes back exactly;
- a DSL that writes a word as a bundle of unit instructions and ports;
- an emulator that runs programs on a model of the datapath and the stream engine, and says how
  sure it is of each result: V (verified on the camera or in the bytes), I (inferred, one step
  beyond) or H (a hypothesis);
- models of two stock programs, the copy and the resampler.

Stdlib only. Stock programs are read from the user's own firmware image at runtime; no stock
microcode is part of this code.

The facts behind each rule (what was measured, how, and at which tier) live in the docstrings and
fact strings of the code that applies the rule. This file says how to use the package.

## Layout

Three layers: encode and decode, the runtime, and the stock models. The first two are the core,
`fenykl.dsp`, whose `__all__` is the API for own programs; they do not import the third,
`fenykl.dsp.stock`, as `tests/test_dsp_layers.py` checks.

| module | contents |
|---|---|
| **encode and decode** | |
| `fields.py` | the field table, the single source of truth: bits, kind, unit, idle value, tier, fact; the op meanings and the datapath facts the emulator uses |
| `units.py` | the units: a strobe and the fields that change under it |
| `word.py` | `Word`, an immutable word with views by field; `IDLE` |
| `asm.py` | the DSL: register files, unit instructions, ports, bundles, `Bundle.of`, the helpers |
| `program.py` | `Program`, `assemble`, `labels`, extraction of the stock programs from a firmware image |
| `disasm.py` | `listing` and `source` |
| **runtime** | |
| `semantics.py` | the datapath rules: op slot, X units, lane functions, lane memory, `UnknownSemantics` |
| `machine.py` | `Machine`, the datapath executor: register files, lane files, lane memory, buses |
| `stream.py` | `Engine`, the stream engine between DRAM and the DSP's memories |

## Writing programs

One bundle is one word. A bundle joins parts with `|`; its word is the idle word with the parts'
fields set.

```python
from fenykl.dsp import A, G, L1, LOAD, NOP, O, OP, S1, X0, Label, to

S1.xor_imm(L1[4], imm=0x20) | to(O[1], S1)  # S1 0x04: b ^ imm into O[1], same word
to(L1[4], LOAD) | OP.add_imm(G[9], 4) | to(G[9], OP)
X0.store(A[1], k=0, o=O[1])  # store O[1] to lane-memory vector A[1] + 0
Label("top") | NOP  # names this word
assert S1(0x04, b=L1[4], imm=0x20).word() == S1.xor_imm(L1[4], imm=0x20).word()
```

**Register files.** `G`, `A`, `B`, `R` are the scalar files of the op slot and the X units,
`F0`..`F3` the scalar files of the S units, `L0`..`L3` their lane files, `U` the lane shifts'
carry file and `O` the store file. `L1[4]` is checked against the file's size, and an operand
takes registers of its own file only.

**Unit instructions.** `S0`..`S3` (the compute slots), `X0`, `X1` (two copies of one ALU, X0
also the lane-memory loads and stores, X1 also the stream transfers) and `OP` (the op slot:
data ops and control ops). Call an instruction by mnemonic, `S1.xor_imm(...)`, or by code,
`S1(0x04, ...)`. `MNEMONICS.md` lists every name with its code, operands, formula and tier; it is
generated by `asm.mnemonics_markdown()` and a test keeps it current. The positional operands are
those the formula reads; the rest are keywords. An immediate shares bits with register operands,
so it also sets those bits; a disagreement or a value out of range raises `ValueError`. Each
instruction carries its `tier`, the weakest of its function's row and its fields. `M(S1)` is the
M strobe on S1: it puts S1's scalar result on X0's result bus.

**Ports.** `to(dst, src)` is the one port of dst's file that writes src: `LOAD` (a lane-memory
load), `S0`..`S3`, `S2_HI` (a product's high half), `X0`, `X1`, or `OP` for the ALU bus. A
(file, source) pair with no port raises `ValueError`.

**What raises.** A field set by two parts, even to one value, and a register written by two
ports raise `ValueError`; only a `raw` part may complete the bits of a field an instruction sets
in part. A register out of range raises `IndexError`, a register of another file and a bare
`Word` in a bundle `TypeError` (use `raw(word)`).

**Labels, NOP, raw.** `Label("top") | ...` names its word; alone it is an idle word. A control
op's target is a word index or a label: `OP.loop(G[8], "top", rr=R[0])`. `NOP` is the empty
bundle, the idle word. `raw(word)` or `raw(f115_119=3)` sets fields directly, by id or by name.
`assemble(bundles, origin=N)` places the words from index N in two passes, so moving the origin
moves every label target; an undefined or duplicate label raises `AssemblyError`. A program
that moves a hypothesis field off idle gets one `HypothesisFieldWarning`.

**Control flow.** The control ops (`loop`, `bz`, `bnz`, `jump`, `ret`) have
`fields.DELAY_SLOTS` (4) delay slots: the words after them run before the transfer. A call, a
`jump` whose slots set the link register, returns to the word after its slots;
`program.call_return_errors` reports calls that would return past the end. `OP.halt()` ends the
job, but the next `emu.HALT_TAIL` (3) words fetched still run, so end a program with idle words
behind its halt, as the kernel example does. Give the control ops `rr=R[0]`: the idle word sets
bits of f120_122 that the machine refuses in a control op.

**Stream helpers.** Constants and the stream engine take a few words each:

- `li(G[9], 4)`: `OP.li` and its port, an immediate sign-extended into the register;
- `b_add(B[12], B[2], 0x1000)`: `X1.add_imm` into B, `dst = src + k`;
- `hand(*values)`: `X1.hand` per value, to the stream engine; a register of B goes as it is, an
  integer through `li` into the `asm.SCRATCH` registers the word before;
- `wait()`: `X1.wait`, waits for the oldest outstanding command;
- `lane_block(channel, nbytes)`, `stream_load(channel, dram, vector)`,
  `stream_store(channel, vector, dram)`: the values that program a channel and its commands, for
  `hand`. `channel` is below `fields.STREAM_CHANNELS` (4), `dram` a register of B, `vector` in
  `asm.HANDED_VECTORS`.

```python
from fenykl.dsp import B, hand, lane_block, stream_load, wait

words = hand(*lane_block(0, 0x1000), *stream_load(0, B[13], 0)) + [wait()]
```

At most `stream.DEPTH` (44) commands may be outstanding; handing more wedges the job on the
camera.

**Lags are the author's job.** The DSL places fields; it does not schedule. Every unit reads the
state from before the word, and every port write lands at the word's end, so a register written
in word t is read from word t + 1. Results arrive on their buses a fixed number of words after
their head, in that word only, and a port at another word writes nothing:

| result | arrives |
|---|---|
| a data op's result, an X unit's result | in the head's own word |
| a multiply's product (`OP.mul`) | `semantics.MULTIPLY_LAG` (1) words later |
| a local-memory load's datum | `semantics.LOAD_LAG` (3) words later |
| a lane-memory load's vector (X0) | `fields.LOAD_LAG` (4) words later |
| X1's divide | `fields.DIVIDE_LAG` (4) words later |
| a lane head's result | per head, `fields.LANE_LAG` |
| S0's and S1's masks on M, S3's reductions | see `fields.S_RESULTS` |

A store head in the word of O's port write stores O's old content; store in the next word:

```python
from fenykl.dsp import A, L1, NOP, O, OP, S1, X0, Boot, assemble, to

words = [
    S1.xor_imm(L1[4], imm=0x20) | to(O[1], S1),
    X0.store(A[1], k=0, o=O[1]),  # one word later: O[1] holds the result
    OP.halt(),
    *[NOP] * 4,
]
prog = assemble(words)
r = Boot().run(prog, regs={"L1": {4: list(range(32))}, "A": {1: 0x40}})
assert r.machine.memory[0x40].lanes[:4] == (32, 33, 34, 35)
```

**Worked example.** `tests/test_dsp_kernel_example.py` is a complete kernel: y = x ^ 0x20 over
a DRAM buffer, streamed through the lane memory in chunks over two banks, the next load handed
before the current compute. A kernel of this shape ran on the camera; the test checks its output
bytes, their tier and its time estimate. Start there.

## Running programs

A `Boot` is one camera boot: DRAM (`put`, `read`), local memory, and what each job leaves for
the next. `Boot.run(program)` steps the program from word 0 on a `Machine` with a fresh stream
`Engine`.

```python
from fenykl.dsp import G, NOP, OP, Boot, Confidence, assemble, li, to

halt = [OP.halt(), *[NOP] * 4]
boot = Boot()
r = boot.run(assemble([li(G[9], 4), OP.add_imm(G[9], 3) | to(G[10], OP), *halt]))
assert r.machine.g[10].value == 7 and r.machine.g[10].tier is Confidence.VERIFIED
r = boot.run(assemble(halt))  # starts with the registers the run before left
assert r.machine.g[10].value == 7
print(r.flow.runs(), r.estimate)
```

`run` takes keywords:

- `regs`: registers to set before the first word, by file and index, over what the last run
  left: an int or an `Sv` in G, A, B, R and F0..F3, a `Vec` or its lanes in L0..L3, U and O.
  Preset the registers a command's CPU setup would provide this way.
- `request`: (offset, bytes) pairs written to local memory first, as a command's setup does.
- `strict`: True by default (below).
- `limit`: the step limit, `emu.STEP_LIMIT` (100000) by default.

A `Run` holds the `job`, the `flow` (every executed word as a `Step`, in order, and why it
stopped), the `machine` (its registers and lane memory at the halt, its stream engine), the
`estimate` and the `lapses`. A run that stops short of its halt raises `NoHalt`, with the flow in
`e.flow`. Each run starts from what the last one left (`Boot.carry`: every register file and the
lane memory, as on the camera); a run that raised, lapsed or did not halt leaves nothing, and
the next starts unknown.

**Strict and lenient.** Strict (the default): a case the facts do not cover raises
`UnknownSemantics`, naming the word and why. Lenient (`strict=False`): the case lapses instead.
What it may write is forgotten, its step is unknown, all the job leaves and decides after it is
a hypothesis, `Run.lapses` says why, the run leaves no carry and its time is not estimated. Use
strict for results; use lenient to see how far a program gets. Some cases raise in either mode:
a step past the program's end, a control word whose target leaves the program.

```python
from fenykl.dsp import G, NOP, OP, R, Boot, UnknownSemantics, assemble

prog = assemble([OP.stw(G[5], 0, rr=R[0]), OP.halt(), *[NOP] * 4])  # G[5] not known
try:
    Boot().run(prog)
except UnknownSemantics as e:
    print(e)
r = Boot().run(prog, strict=False)
assert r.lapses and r.estimate.us is None
```

## Reading results

`Boot.read(addr, n)` returns `Bytes`: per byte its value (`data`), whether it is known
(`known`), its tier (`taint`) and its provenance (`src`, an index into `Boot.sources`, and `off`,
the offset in that source). An unknown byte's source says why it is unknown. `weakest()` gives
the weakest tier of the known bytes, `ranges(known)` the runs of known or unknown bytes,
`segments()` the runs that continue one source. Registers are `Sv` scalars and lane registers
`Vec` vectors of `semantics.LANE_COUNT` (32) lanes, with None where not known, each with its tier. The
emulator never guesses: a value no fact gives is unknown.

A result's tier is the weakest tier of every rule that produced or moved it, and of the control
decisions that led there. Listings mark the tiers `!` (verified) and `~` (inferred); unmarked is
a hypothesis.

`Run.estimate` is the job's minimum time on the camera as an `Estimate`: `us` (None when not
known; `unknown` says why), `tier` and `parts`, each a named `Part` with its own time and tier.
The parts are the fixed cost per job, `timing.JOB` (97.9 us); the first run of each word,
`timing.FIRST` (0.064 us); each word that never runs in a fetch line of `timing.LINE` (8) words
that runs, `timing.UNRUN` (0.064 us); each repeated word, `timing.REPEAT` (0.0052 us); and what
the stream waits do not hide (`timing.RATES`). Single jobs jitter on the camera; the estimate is
the minimum over repeats (`timing`'s docstring). A case that was not timed makes the estimate
unknown rather than guessed, among them more than `timing.QUEUE` (16) commands handed before
their wait.

## Reading programs

```python
from fenykl.dsp import L1, NOP, O, OP, S1, Bundle, assemble, listing, source, to

prog = assemble([S1.xor_imm(L1[4], imm=0x20) | to(O[1], S1), OP.halt(), *[NOP] * 4])
assert "s1: op=4~ b=4! imm=0x20!  pb: osrc=3! odst=1!" in listing(prog)
print(source(prog))  # DSL source that assembles back to the same words
assert repr(Bundle.of(prog.words[0])) == "S1.xor_imm(L1[4], 0x20) | to(O[1], S1)"
```

`listing` shows per word the fields that differ from the idle word, grouped by unit, under their
names or ids, each with its tier mark; `|` after the index marks a delay slot, `-> T` a control
target. `source` prints Python that rebuilds the program; with `labels(bundles, origin)` it
names targets by label. `Bundle.of(word, labels, at)` reads any word back as a bundle, exactly:
fields that no instruction or port expresses go in a `raw(...)` part.

**Read sets.** A head reads only some of its unit's operands: `semantics.head_reads(unit, word)`
gives them, None where they are not known. Listings and `Bundle.of` show a head by the operands
it reads, then any other bit that differs as a raw field, so a listing never hides a bit. A head
whose read set is not known shows every operand that differs.

## The stock models

`fenykl.dsp.stock` models the copy (program 16, cmd 0xF) and the resampler (program 13,
cmd 0xC). No stock word is decoded: each model is built at runtime from the user's firmware
image and the outcomes measured on the camera. A `StockBoot` is a `Boot` with the state the
models keep across jobs; `run_model(boot, model, job)` runs a job by its model.

```python
# image: the stock E-M10 II firmware .BIN, as bytes
from fenykl.dsp.stock import commands, taps
from fenykl.dsp.stock.copy import Copy16Model
from fenykl.dsp.stock.model import StockBoot, run_model
from fenykl.dsp.stock.resample import (
    H_MAX,
    ONE,
    PLANES,
    STRIDE,
    Resample13Model,
    predict,
)

SRC, DST, data = 0xA0000000, 0xA1000000, bytes(range(256)) * 4
copy = Copy16Model.from_image(image)
boot = StockBoot()
boot.put(SRC, data, "src")
result = run_model(boot, copy, commands.copy(copy.program, SRC, DST, len(data)))
assert bytes(boot.read(DST, len(data)).data) == data

resample = Resample13Model.from_image(image)
h = H_MAX
src = bytes(i & 0xFF for i in range(PLANES * STRIDE * h))  # three planes of STRIDE x h
table = [(i * ONE, ONE) for i in range(h)]  # per output line: source line a, step b
unit = (0, taps.ONE, 0, 0)  # every phase passes tap 1's line
p = predict(resample, taps.Taps.of([unit] * taps.PHASES), src, table)
assert all(p.dst.known)
```

Strict, a job word the model does not cover raises `UnknownSemantics`; lenient
(`run_model(..., strict=False)`) runs the stock word there and taints the job a hypothesis. The
model modules' docstrings give the confidence rule (`stock/model.py`), what is known of each
stock word (`stock/copy.py`, `stock/resample_edits.py`) and the resampler's law
(`stock/resample.py`). The curated camera vectors are in `tests/data/dsp/`.

## The CLI

- `fenykl dsp disasm ITEM [FILE.BIN]`: a stock program's listing;
- `fenykl dsp source ITEM [FILE.BIN]`: a stock program as DSL source; it reproduces stock
  microcode from your image, for local work only, never commit it;
- `fenykl dsp fields`: the field table, the op meanings and the delay-slot rule;
- `fenykl dsp flow [--len LEN] [--src SRC] [--dst DST] [--branch INDEX=0|1] [FILE.BIN]`: steps
  the stock copy on the datapath executor, lenient, and prints the executed words; `--branch`
  decides a conditional control op in place of the machine.

FILE.BIN defaults to the stock image in `firmware/`.

## Limits

The emulator models what was measured and nothing else. Not modelled or not measured, among
others: heads without a measured rule or lag, combinations of M results not measured, stream
command kinds and shapes that never ran, races between a command and the words beside it, and
time for anything not timed. It shows in three ways:

- strict, `UnknownSemantics` names the word and the case;
- lenient, the case lapses (`Run.lapses`), and what follows is unknown or a hypothesis;
- the estimate is unknown, with `Estimate.unknown` saying why.

A value is never filled in by a guess; an unknown byte carries the source that explains it.

## Adding a semantic

- **A datapath rule** (a lane function, an X function, a data op, a lag): add its row to the
  table in `fields.py` (`LANE_FUNCTIONS`, `X_FUNCTIONS`, `LANE_LAG`, ...) or the op's entry in
  `semantics.OP_SEMANTICS`, with its tier and its fact. Tag the fact by how it was measured.
- **A field**: edit `fields.FIELDS`. Split or merge entries so that every bit stays covered
  once (the import raises otherwise), and give each new entry its idle value, kind, tier and a
  one-line fact. An id names both ends of the field's bits, so DSL source naming an old id fails
  loudly.
- **A stock model fact**: the outcome of a stock word goes in `copy._PARTS` or a role's table in
  `copy._CHANNELS`, a register value in `stock/registers.py`, a resampler edit in
  `resample_edits.FACTS` or `resample_window.SEMANTICS`. The docstrings there say which tier
  each kind of fact takes.

Each semantic carries its tier, and a test should come with it.
